# نسخة المشرف والمراجعين — التصور التنفيذي

## الهدف

إتاحة نسخة بحثية نظيفة لمشرف واحد أو عدة مشرفين لتجربة كتب يحددها المالك، والاستماع إلى النتائج المحفوظة، وتسجيل الملاحظات؛ دون كشف أدوات المالك أو تشغيل عمليات مدفوعة.

## الأدوار

- `owner`: المالك؛ يحتفظ بجميع وظائف الإدارة والرفع والمعالجة.
- `reviewer`: مشرف أو مراجع مدعو؛ قراءة وتقييم فقط.
- `user`: المستخدم المستقبلي؛ يدير مكتبته الخاصة وفق المنتج المعتمد لاحقًا.

لا يُنشأ تطبيق منفصل. تستخدم المنصة نفسها واجهة مختلفة وصلاحيات مختلفة حسب الدور، لتجنب اختلاف النسخ وصعوبة صيانتها.

## دخول المشرف

- دعوة مرتبطة ببريد المشرف، وليست رمزًا عامًا مشتركًا.
- رابط دخول مؤقت أو تسجيل بالبريد، مع صلاحية يمكن إنهاؤها.
- رقم بحثي ظاهر مثل `R-001` بدل إظهار بيانات شخصية داخل واجهة الدراسة.
- لا يستطيع المراجع إنشاء حساب مراجع من صفحة التسجيل العامة.

## ما يراه المراجع

- تحية عامة: «مرحبًا بك في المكتبة الشخصية الذكية».
- الكتب التي اختار المالك مشاركتها معه فقط.
- الغلاف، البطاقة الوصفية، الخلاصة، التحليل، الفصول، الأسئلة المحفوظة، والصوت المحفوظ.
- تشغيل الصوت المكتمل دون أي زر إنشاء أو شراء أو استكمال.
- نموذج تقييم وملاحظات مرتبط بالمراجع والكتاب وتاريخ الإرسال.
- تسجيل الخروج، اللغة، المظهر، وتنشيط الصفحة.

## ما لا يراه ولا يستطيع تنفيذه

- اسم عبدالرحمن أو عبارات المالك الشخصية.
- الأسعار، التكلفة، الرصيد، حدود الاستخدام، الشراء، أو تفاصيل API.
- رفع كتاب، إعادة رفع الأصل، حذف، أرشفة، استعادة، أو تعديل الفهرسة والتصنيف.
- إنشاء تحليل أو ترجمة أو سؤال أو عينة صوت أو صوت كامل.
- رؤية البريد الشخصي للمالك، مسارات التخزين، إقرارات الحقوق الداخلية، أو سجلات الدفع.
- رؤية كتب لم يمنحها المالك له صراحة.

## نموذج الملاحظات

- التقييم العام من 1 إلى 5.
- سهولة الاستخدام.
- جودة الخلاصة والتحليل.
- جودة الصوت.
- فائدة العودة إلى مواضع الكتاب.
- مشكلة واجهها المراجع.
- اقتراح تطوير.
- موافقة منفصلة على استخدام التقييم في الدراسة بصيغة مجهلة.

## نموذج البيانات المقترح

- `spl_profiles`: المستخدم والدور.
- `spl_review_invites`: الدعوة، البريد، الحالة، والانتهاء.
- `spl_book_shares`: المراجع، الكتاب، المالك، تاريخ المنح والانتهاء.
- `spl_reviewer_feedback`: التقييمات والملاحظات والموافقة البحثية.

## الحماية المطلوبة

- تطبق صلاحيات القراءة في Supabase RLS، لا في إخفاء أزرار الواجهة فقط.
- لا تمنح للمراجع سياسات `insert/update/delete` على الكتب أو المخرجات.
- الصوت والأغلفة تظل خاصة وتصدر روابط مؤقتة بعد التحقق من المشاركة.
- إلغاء الدعوة أو المشاركة يوقف الوصول فورًا.
- سجل تدقيق لمن منح الوصول ومن ألغاه ومتى، دون تسجيل محتوى القراءة.

## مراحل التنفيذ

1. اعتماد هذا التصور والنصوص الظاهرة للمراجع.
2. إضافة الجداول وسياسات RLS في Migration مراجعة غير مطبقة.
3. إضافة اكتشاف الدور وبناء واجهة `reviewer` المقيدة.
4. إضافة لوحة المالك لاختيار الكتب ودعوة المشرف.
5. إضافة نموذج التقييم ولوحة قراءة النتائج.
6. اختبار فصل الحسابات ومنع جميع عمليات الكتابة والمدفوعات.
7. دعوة مشرف تجريبي واحد، ثم التوسع بعد نجاح الاختبار.

## معيار القبول

لا تُعتمد نسخة المشرف حتى تثبت الاختبارات أن حساب المراجع لا يستطيع قراءة كتاب غير مشارك، أو تشغيل وظيفة مدفوعة، أو تعديل أي سجل حتى عند إرسال الطلب مباشرة خارج الواجهة.
